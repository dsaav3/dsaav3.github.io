What was harder than expected
The most difficult aspect of this project was debugging silent failures in the RTOS environment, specifically when deploying the web server on the ESP32. Initially, I could not get the server to deploy from Wokwi. My strategy was to trace the network initialization, adding multiple print statements to the serial monitor to verify that the ESP32 was properly connecting to Wi-Fi. The telemetry confirmed the network connection was successful and the server was attempting to initialize, but the system kept crashing without throwing a clear error. Ultimately, I discovered the issue was memory-related: the default stack size allocated to the web server task was too small to handle the HTML/JSON payload, causing a silent overflow. Expanding the stack size instantly fixed the issue, but it taught me how difficult it is to debug embedded systems when failures don't present as standard logic errors.

What I would do differently
If I were to rebuild this system, I would spend significantly more time upfront mapping out memory allocations and a strict priority band for all tasks before writing any code. I learned that determining task priorities is a delicate balancing act—hardware sensors require a specific priority, control loops require another, and background tasks like logging or web monitoring must sit at the bottom. Additionally, I would implement the "bottom-half" interrupt strategy much earlier. Instead of trying to process data inside the ISR (Interrupt Service Routine), which blocks the system, I would keep the ISR as short as possible and use it solely to trigger a bottom-half software task. Planning this RTOS architecture thoroughly from day one would have prevented many of the latency and memory issues I faced later in development.

The most valuable thing I learned
The most profound takeaway from this course is the direct connection between real-time embedded constraints and human safety. The medical world relies on an infinite number of hard real-time systems—from pacemakers and ECG monitors to automated patient beds. In these systems, a late calculation is a failed calculation that can cost a life. Understanding how to guarantee deterministic behavior through proper queue sizing, memory management, and dual-core isolation was eye-opening. As I prepare to graduate with my Computer Engineering degree and begin working at Texas Instruments, this mindset is exactly what I will carry forward. TI produces a massive amount of electronics for the automotive and industrial sectors, where a failed real-time constraint on an assembly line or in a vehicle braking system can cause real physical damage. This class bridged the gap between writing code and engineering safe, production-ready electronics.
